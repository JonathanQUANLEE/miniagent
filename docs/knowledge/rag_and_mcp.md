# RAG 与 MCP

## RAG（检索增强生成）

LLM 的知识停在训练截止日，也装不下企业的私有文档。RAG 的思路是"开卷考试"：先从资料库里检索出最相关的几段原文，再把原文塞进提示词让模型据此回答。

全链路五步：① 文档切片（把长文档切成小块）② 向量化（Embedding，把文字变成向量）③ 入库（向量数据库或简单数组）④ 检索（问题也向量化，算余弦相似度，取 Top-K）⑤ 生成（把检索到的资料连着问题一起交给模型，要求标注引用）。

RAG 和上下文压缩是一对对偶问题：上下文窗口有限，RAG 是"按需取用"，压缩是"丢了细节留结论"。

## MCP（Model Context Protocol）

MCP 是工具界的 USB-C：以前 N 个 Agent 接 M 个工具要写 N×M 份定制集成，有了标准协议只要 N+M 份。协议本体是 JSON-RPC 2.0，三个核心方法：

- initialize（握手，交换协议版本和能力）
- tools/list（拉取工具菜单）
- tools/call（调用某个工具）

stdio 传输用"一行一条 JSON"分隔请求和响应；日志必须走 stderr，stdout 只留给协议通道。MCP 拉到的远端菜单可以直接挂进 Agent 的工具注册表——模型依旧只认菜单，点菜逻辑一行不用改。
