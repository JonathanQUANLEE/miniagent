
# 代码审查技能（code-review）

## 任务

按以下四步法审查指定文件，找出其中的错误，
最后按【报告格式】输出完整审查报告。

## 铁律

- 只审查、只报告，不修改目标文件（除非用户明确要求修复）
- 每一步都必须动手取证（读文件 / 实际运行），禁止凭空猜测
- 报告必须按四步结构输出，缺一步不合格

## 流程（必须按顺序执行）

### 第 1 步：案发地点

用 read_file 读取用户指定的目标文件，获得全部代码。
逐行通读一遍，标记所有可疑行：

- 拼写可疑：函数名、变量名是否像拼错了（如 prnt、retrun）
- 未定义可疑：用到的名字，是否在本文件或菜单工具里定义过
- 结构可疑：缩进是否对齐、冒号是否缺失、括号引号是否配对

### 第 2 步：指认现场

用 run_command 实际运行目标文件（command 填：python 目标文件路径），
拿到真实的退出码、stdout、stderr。

- 退出码 0：文件能跑，重点转为逻辑检查
- 退出码非 0：stderr 里就是真凶口供——
  记下 Traceback 中的文件名、行号、错误类型（罪名）

### 第 3 步：罪名判定

把第 1 步的可疑行 与 第 2 步的 Traceback 对照：

- NameError → 有名字没定义（对照第 1 步的拼写可疑行）
- SyntaxError → 结构问题（冒号/括号/缩进）
- TypeError → 类型不匹配（文字条 + 数字相加之类）
  每一处错误，判定它的罪名和案发行号。

### 第 4 步：死因与修复建议

对每一处罪名，用一句话说明：

- 为什么会死（机器视角：Python 为什么停在这）
- 怎么修（修复建议，但如果用户只要求审查，就只建议不动手）

## 报告格式

# 审查报告：〔文件名〕

## 第 1 步 案发地点

（通读结论：文件是干嘛的 + 可疑行清单）

## 第 2 步 指认现场

（运行命令 + 退出码 + stderr 关键内容）

## 第 3 步 罪名判定

（每处错误：行号 + 罪名 + 证据）

## 第 4 步 死因与修复建议

（每处错误的死因一句话 + 修复建议一句话）
